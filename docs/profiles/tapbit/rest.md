# Tapbit REST Profile

**Status:** Done.

**Retrieved:** 2026-09-22.

**Probed:** 2026-09-22 local time, 2026-09-23 03:21 to 03:37 UTC, from the development host near Seattle.
Every documented perpetual path refused this host with HTTP 403, so the catalog, anchor and book sections below are documented and not probed.

This profile covers the public REST API of Tapbit for its USDT-margined perpetuals, the only perpetual family, see [`fees.md`](./fees.md) section 3.
Tapbit has no CCXT class in 4.5.68 or in the current master, see [`fees.md`](./fees.md) section 8.
The probe is [`rest-probe.mjs`](../../../scripts/probes/venues/tapbit/rest-probe.mjs).

The refused requests carried `server: CloudFront` and `x-cache: Error from cloudfront`, and no `Retry-After`.
Over `http://` every path answered 301 to the same `https://` URL.
A browser `user-agent` and an `accept: application/json` header got the same 403 on the perpetual catalog.

The pattern reads as a firewall at the CloudFront edge that lets `/spot-v2/` through and refuses every other path, including a path that does not exist, before it reaches Tapbit's `nginx`.
That matches the documentation.
The perpetual, spot and spot v2 changelogs all carry the entry of 2024-12-13, "All clients should be added into whitelist so that they can visit the API.", S2.
The help center says the spot API is open to every KYC-verified user while the futures API needs an application, S9, which explains why `/spot-v2/` is open.
Whether the whitelist is also a country rule cannot be told from one host, and no other route was tried.

### Pairs listed twice, price scale and deny list input

The 116 CoinGecko perpetuals have 116 distinct bases, so no pair appears twice under one ticker, P5.
Two underlyings do appear under two tickers each.
At 03:30 UTC `SKHY` read 191.47 and `SKHYNIX` read 1,371.16, two tickers that by their names both follow SK Hynix at different scales, which is an inference.
`GOLD` read 4,339.8 beside `XAUT` at 4,340.4, P5.
Three contracts are quoted per 1,000 units, `1000BONK`, `1000PEPE` and `1000SHIB`, and would need a price scale, P5.
The TradFi and pre-IPO contracts, among them `OPENAI`, `ANTHROPIC`, `GOLD`, `SILVER(XAG)`, `OIL(WTI)`, `SAMSUNG`, `SKHYNIX` and `SKHY`, would need a `DENIED_PAIRS` check, since another venue's contract of the same ticker may track a different underlying, P5.
Pre-IPO contracts can be rebased, which divides the price by the rebase multiplier in one step, S18.

## 4. Anchor semantics

### Index

"The Price Index is a bucket of prices from the major Spot market exchanges, weighted by their relative volume.", S12.
The named sources are Binance, Bybit, OKX, Gate.io, KuCoin, Bitstamp, Coinbase Pro, Kraken, Gemini and Bittrex, in an article dated 2025-03-18 that names no per contract basket.

| rule | value | source |
|---|---|---|
| stale source | a source whose price is more than 15 minutes old, with no trade for 15 minutes, is dropped and the weights renormalise | S12 |
| no source at all | "the spot price of the corresponding trading pair on Tapbit will serve as the index price" | S12 |
| outlier at 1 % | the top or bottom source more than 1 % beyond its neighbour has its weight cut to 1/N | S12 |
| outlier at 3 % | the top or bottom source more than 3 % beyond its neighbour is excluded | S12 |
| basket call | none public | S2 |
| TradFi index | Not publicly specified | S19 |

The fallback to Tapbit's own spot price is the self-referential shape that made a mark trail its own perpetual in [`2026-09-15-one-self-index-fresh-gate.md`](../../research/2026-09-15-one-self-index-fresh-gate.md).
Here it is a fallback and not the basket, and when it applies cannot be seen without a basket call.

### Mark

"Mark Price = Median (Price1, Price2, Latest Contract Price)", S13, S14.

| term | formula | source |
|---|---|---|
| Price1 | `Index Price * (1 + Latest Funding Rate * (Time Until Next Funding / Funding Interval))`, with the time rounded down to whole hours in the example, 5.5 h read as 5 | S13 |
| Price2 | `Index Price + Moving Average (2-Minute Basis)`, the mean of 24 samples of `(bid1 + ask1) / 2 - index`, one every 5 s | S13 |
| clamp | none documented. The median itself bounds the mark between the two index-based prices and the last trade | S13 |

So the mark equals the last trade whenever the last trade lies between Price1 and Price2.
A thin contract's mark can therefore follow its own last trade, which is a mark that tracks the perpetual rather than the index.
The formula was announced for "September 5th at 07:00 AM UTC" with no year, in an article created 2025-03-18 and updated 2025-12-29, S14.

### Funding

`F = P + clamp(I - P, 0.05%, -0.05%)`, with an absolute cap of 75 % of the initial margin minus the maintenance margin, and a change limit of 75 % of the maintenance margin between intervals, S11.
The call returns "the latest funding rate of the current contract", S2, and whether that is the upcoming or the last settled rate is Not publicly specified.
The settlement instant itself was not captured, and no funding history call is documented.
The full cost view is in [`fees.md`](./fees.md) section 6.

### How often each number changed

Not measured, because every anchor call refused this host.

## 5. REST book snapshot

`GET /swap/api/usdt/instruments/depth?instrument_id=&depth=`, depth 5, 10, 50 or 100 with 10 by default, "10times / 1second", S2.
Each level is `[price, quantity, order count]` as strings, asks ascending and bids descending in the documented example.
Caching is Not publicly specified.
It refused this host, P1.

The spot v2 book did answer, as `{"code":200,"message":null,"data":{"asks":[["86677.74","0.648"],...],"bids":[["86675.69","10.2068"],...],"timestamp":1790134098524}}`, with two fields per level and no order count, in 123 and 142 ms, P4.

## 6. Rate limits and errors

| call | documented limit |
|---|---|
| `instruments/list`, `ticker_list`, `ticker_one`, `funding_rate`, `trade_list`, `candles` | 3 per second, lowered from 10 on 2024-03-17 |
| `instruments/depth` | 10 per second |
| `v1/usdt/time` | 5 per second |
| spot v2 `trade_pair_list` | 1 per second |
| spot v2 `ticker_list`, `depth` | 2 per second |
| spot v2 `current/timestamp` | 5 per second |

All limits are from S2.
They count per public IP without an API key and per user with one, and a limit returns HTTP 429 "Request too frequently", S2.
No 429 and no `Retry-After` was seen, since no request reached a limit.
The documented error body is `{"code": 10001, "msg": "Invalid Paramater."}`, S2.
HTTP 504 "does not mean that the request failed, but is unknown", S25.

The whitelist refusal is an HTTP 403 with an HTML body.
The engine counts 403 as a rate limit, at [`errors.ts`](../../../server/src/shared/errors.ts) line 1, so a poller on a host outside the whitelist would pause and retry forever instead of failing.

## 7. Server time and clock offset

The perpetual time call `GET /swap/api/v1/usdt/time`, documented as `{"iso": "...", "epoch": "1681201809.956"}`, refused this host, P1.
The spot v2 time call `GET /spot-v2/api/spot/instruments/current/timestamp` answers in Unix ms, and 10 warm reads over two runs gave offsets of -14.5 to +54.5 ms against this host's clock with round trips of 119 to 261 ms, P3.
Every offset lies inside half its round trip, so the clocks agree to within the measurement.

## 8. Recommended poller shape

No poller is recommended, because the anchor calls refuse this host and the futures API is granted only to approved accounts, see [`fees.md`](./fees.md) section 1.
Even with access, no REST call carries the index, and the funding rate is one contract per call.
If a host is ever put on the whitelist, the following is a draft, not a decision.

| item | draft | reason |
|---|---|---|
| source | the WebSocket topic `usdt/ticker.all`, held as a live table and read by the poller each second | the only bulk source of index, mark and rate |
| cross-check | `ticker_list` every few seconds for `mark_price` | a REST check that the socket table is fresh |
| interval | 8 h by default, overridden per contract from the help center's interval notices | no field carries it |
| next settlement | the next 00:00, 08:00 or 16:00 UTC for 8 h contracts, and Not verified for 1 h and 4 h contracts | no field carries it |
| skip | pre-IPO contracts, and TradFi contracts until their index is documented | rebase steps and an undocumented index |
| rate limit pause | treat the whitelist 403 as fatal rather than as a rate limit | section 6 |

That shape is a socket-fed anchor, which the engine's `AnchorPoller` does not support today.
